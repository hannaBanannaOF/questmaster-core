# Proposal

## Why

`GET /campaign` and `GET /character` return every item the user has, in no defined order. Clients that only show a few items, like the frontend dashboard (5 characters, the DM's campaigns, one "continue playing" campaign), download the whole list and filter it themselves. That cost grows with the user's data, and without an `ORDER BY` the order can change between requests, so clients cannot page through the lists either.

## What Changes

- **BREAKING**: `GET /core/api/v1/campaign` and `GET /core/api/v1/character` return `{ "items": [...], "total": N }` instead of a bare array. `total` counts every item matching the filters, ignoring pagination.
- Both lists accept `limit` (default 50, maximum 100) and `offset` (default 0). Invalid values return 400.
- Both lists have a stable order: name (case and accent insensitive), then id.
- The campaign list accepts `role` (`dm` or `player`) and `status` (a campaign status) filters, so clients can ask for "my ACTIVE campaigns as a player" without loading the rest.
- The campaign list is built by a single query, instead of merging the DM and player queries in the use case, so pagination and `total` are correct across both roles.

Out of scope: cursor pagination, sorting options chosen by the client, and paginating the characters inside the campaign details.

## Capabilities

### New Capabilities
- `character-list`: Which characters appear in the user's character list, its filters, order and pagination.

### Modified Capabilities
- `campaign-list`: Adds the order, the `role` and `status` filters and pagination.

## Impact

- **API**: Breaking response shape for both list endpoints. The frontend is the only client and must be released together.
- **Code**: campaign and character list queries and repositories, list use cases and commands, query filter parsing, list responses and mappers, Swagger annotations (regenerated by CI).
- **Frontend**: list repositories read `items` and `total`; the dashboard asks for what it shows (`limit=5`, `role`, `status`) instead of filtering whole lists.
