# Proposal

## Why

After creation, only a character's current HP can change. Max HP grows as characters level up or recover, a typo in the name stays forever, and a character created without HP (including a premade character) can never get HP.

## What Changes

- **Edit a character's name and max HP** through `PATCH /core/api/v1/character/{characterID}` with `name` and/or `max_hp`. Allowed for the character's player and for the DM of the character's campaign, the same people who may update HP; for an unclaimed premade character, its campaign DM.
- Lowering max HP below the current HP lowers the current HP to the new max. Setting max HP on a character without HP gives it HP, with current HP equal to the max.
- **BREAKING for links**: renaming regenerates the slug from the new name, so the slug always matches the name; the old slug stops resolving.

Out of scope: changing the game system or removing a character's HP.

## Capabilities

### New Capabilities
- `character-edit`: Who can edit a character's name and max HP, and how HP and the slug follow.

### Modified Capabilities
- `slugs`: A character's slug is also regenerated when its name changes.

## Impact

- **API**: new `PATCH /character/{characterID}` returning the updated slug, name, current HP and max HP; a migration makes the character slug trigger also run when the name changes.
- **Code**: character domain (`Rename`, `SetMaxHP`, reusing `CanUpdate`), an edit use case, a repository update, handler, request validation and Swagger annotation (regenerated by CI).
- **Frontend**: an "Editar" dialog on the character sheet, for the player and the campaign DM, which redirects to the new slug after a rename.
