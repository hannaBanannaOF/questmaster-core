# Design

## Context

See proposal.md (Why). `Character` has a `CharacterName` value object, an optional `*HP` (`NewHP(current, max)` validates `max > 0` and `0 <= current <= max`) and `CanUpdate(user, campaign)` (player or campaign DM), used by `UpdateHP`. The slug is generated by the `trg_generate_slug` trigger, `BEFORE INSERT` only; its uniqueness loop already skips the row's own id.

## Goals / Non-Goals

**Goals:**
- One partial-update endpoint for the fields a sheet edit needs, with the same permission as HP.

**Non-Goals:**
- Changing the game system (it ties the character to campaigns of that system).
- Removing HP from a character.

## Decisions

**`PATCH` with optional fields.** The request has `name *string` and `max_hp *int`; both nil is 400. Alternative: one endpoint per field. Rejected: the frontend edits both in one dialog and one call keeps them consistent.

**Domain methods reuse `CanUpdate`.** `Character.Edit(user, campaign, name *CharacterName, maxHP *int)` checks `CanUpdate`, then renames and calls `SetMaxHP`, which clamps the current HP (`min(current, max)`) or creates `HP{max, max}` when there was none. For an unclaimed premade character `IsPlayer` is false for everyone, so only the campaign DM passes, which is the intended rule.

**Slug follows the name, in the database.** Migration `0008` recreates the character trigger as `BEFORE INSERT OR UPDATE OF name`, reusing the same function, so creation and rename share one slug rule; the down migration restores `BEFORE INSERT`. Saving the same name yields the same slug because the uniqueness loop skips the row itself. The repository returns the new slug (`RETURNING slug`). Alternative: keep the old slug and redirect from it. Rejected for now: it needs a slug history table, and a sheet link is rarely shared outside the app.

## Risks / Trade-offs

- [Old links to a renamed character break] → The frontend redirects to the new slug right after the edit; other open tabs land on "not found" and the character is found again from the lists. A slug history with redirects can come later if needed.
- [The DM lowers a player's max HP] → Same trust as the existing HP update by the DM.
