# Proposal

## Why

The redesigned frontend dashboard shows, on each character card, the campaign the character plays in (or "No campaign"), and gives the DM a "Needs you" section with the campaigns nobody joined yet. Today the character list does not say which campaign a character is in, and the campaign list cannot filter campaigns without players, so the frontend would need one request per character or would have to filter a preview page client-side (wrong counts beyond the first page).

## What Changes

- **Character list item gains `campaign`**: `{ "slug": string, "name": string }` of the campaign the character is linked to, or `null` when it is in none. Same visibility as today: only the requester's own characters.
- **Campaign list gains the `without_players` filter**: `without_players=true` keeps campaigns with `player_count = 0` (same player count the item already reports). It combines with `role`, `status` and `sort`, and `total` reflects it.

Out of scope: listing every campaign of a character (a character is in at most one campaign today).

## Capabilities

### Modified Capabilities
- `character-list`: Each item includes its campaign.
- `campaign-list`: New `without_players` filter.

## Impact

- **API**: additive `campaign` field on `GET /character` items; new optional `without_players` query on `GET /campaign`. No breaking change.
- **Code**: character list query joins the campaign (slug, name); campaign list query adds the player-count condition; DTOs and Swagger annotations (regenerated by CI).
- **Frontend**: dashboard character cards and the DM "Needs you" section (`questmaster-frontend/openspec/changes/dashboard-redesign`). The frontend tolerates the old API until this ships.
