# Proposal

## Why

The redesigned campaign list in the frontend has a search field: with dozens of campaigns, finding one by name is the fastest path. The campaign list has no name filter, and the core ignores unknown query parameters, so today the search would silently return the unfiltered list.

## What Changes

- **Campaign list gains `q`**: keeps campaigns whose name contains `q`, ignoring case and accents (the same normalization as the name ordering). Leading and trailing spaces are trimmed; an empty `q` is no filter. It combines with `role`, `status`, `without_players`, `sort` and pagination, and `total` reflects it. Longer than 100 characters MUST return 400.

Out of scope: searching by system, overview or character names.

## Capabilities

### Modified Capabilities

- `campaign-list`: New `q` filter.

## Impact

- **API**: new optional `q` query on `GET /campaign`. No breaking change.
- **Code**: filter parsing in `transport/http/filters.go`, an unaccented `ILIKE` condition in the list and count queries, Swagger annotation (regenerated by CI).
- **Frontend**: campaign list search (`questmaster-frontend/openspec/changes/campaign-list-redesign`), which already sends `q`.
