# Proposal

## Why

The redesigned character list in the frontend has a search field, like the campaign list (`campaign-list-search`). The character list has no name filter, and the core ignores unknown query parameters, so the search would silently return every character.

## What Changes

- **Character list gains `q`**: keeps the requester's characters whose name contains `q`, ignoring case and accents. Leading and trailing spaces are trimmed; an empty `q` is no filter. It combines with `game_system`, `without_campaign`, `sort` and pagination, and `total` reflects it. Longer than 100 characters MUST return 400.

## Capabilities

### Modified Capabilities

- `character-list`: New `q` filter.

## Impact

- **API**: new optional `q` query on `GET /character`. No breaking change.
- **Code**: filter parsing and an unaccented "name contains" condition in the list and count queries, sharing the normalization with `campaign-list-search`; Swagger annotation (regenerated by CI).
- **Frontend**: character list search (`questmaster-frontend/openspec/changes/character-list-redesign`), which already sends `q`.
