# Proposal

## Why

The core stores hit points for every character, but HP is a rule of some game systems, not of characters in general: D&D and Call of Cthulhu have HP, Ghostbusters has none, and each system names and bounds its main attribute differently. Each game system will keep its own attributes in its system-specific service, so the core should only hold what every character shares: name, player, game system and campaign.

## What Changes

- **BREAKING**: `PATCH /core/api/v1/character/{characterID}/hp` is removed.
- **BREAKING**: `current_hp` and `max_hp` are removed from every response: character list and details, campaign details (party and premade characters) and invite details (premade characters).
- **BREAKING**: character creation no longer accepts `hp`, premade creation no longer accepts `max_hp`, and character editing only changes the name (`max_hp` is no longer accepted).
- **BREAKING (data)**: a migration drops `character_sheet.max_hp` and `character_sheet.current_hp`. Existing HP values are deleted; the down migration recreates the columns empty.

## Capabilities

### New Capabilities

None.

### Modified Capabilities
- `character-hp`: All requirements removed.
- `character-edit`: Editing only renames; max HP and its effect on current HP are removed.
- `campaign-details`: Party and premade characters no longer carry HP.
- `campaign-invites`: Premade characters in the invite details no longer carry HP.
- `premade-characters`: Creation no longer takes a max HP.
- `campaign-membership`: A removed character no longer keeps HP (it has none).

## Impact

- **API**: breaking removals above; the frontend and the system-specific services must be released together with this change.
- **Database**: migration `0009` dropping the two HP columns, irreversible for the data.
- **Code**: character domain (`HP` type, errors), the update HP use case and endpoint, create, premade and edit use cases, repositories, read models, responses and mappers of characters, campaigns and invites, error mapping, Swagger annotations (regenerated by CI), README.
