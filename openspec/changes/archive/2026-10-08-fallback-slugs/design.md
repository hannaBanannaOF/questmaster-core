# Design

## Context

Slugs are generated by the `BEFORE INSERT` triggers created in migrations 0002 and 0003, using `unaccent`, which strips accents but does not transliterate non-Latin scripts. The Go `Slug` value object rejects anything not matching `^[a-z0-9-]+$`, including the empty string.

## Goals / Non-Goals

**Goals:**
- No campaign or character can end up with an empty slug.

**Non-Goals:**
- Transliterating non-Latin scripts into readable slugs (would need a new extension or library).
- Fixing the race where two concurrent inserts with the same name compute the same slug.

## Decisions

**Fallback in the trigger, not validation in the domain.** The trigger function uses `campaign` or `character` as the base when the derived slug is empty. Alternative: reject such names in `NewCampaignName`/`NewCharacterName`. Rejected by product decision: users must be able to use names in any script.

**Fix existing rows in the same migration.** A `DO` block assigns each row with an empty slug the next free `campaign[-N]` or `character[-N]` slug, using the same uniqueness loop as the trigger. Without it, owners of existing rows would keep getting 500s.

**Down migration restores the original functions only.** Rolling back does not restore empty slugs, since they were never valid.

## Risks / Trade-offs

- [Fallback slugs are not descriptive ("campaign-7")] → Acceptable: slugs only need to be unique and URL-safe; the name is shown in the UI.
