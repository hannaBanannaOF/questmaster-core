# Proposal

## Why

A code review found that any authenticated user could create an invite for any campaign and read any campaign's details, including its invite hash, which let anyone join any campaign. The same review found three requests that crashed the handler with a nil pointer panic, and 500 responses that exposed internal error text (such as database errors) to clients.

## What Changes

- **BREAKING**: Creating a campaign invite is restricted to the campaign DM. Other users get 403, and a missing campaign gets 404.
- **BREAKING**: Campaign details are restricted to the DM and to players with a character in the campaign. Other users get 403.
- **BREAKING**: The campaign details response only includes `invite_hash` for the DM. It is `null` for players.
- Updating HP of a character that has no HP returns 400 instead of crashing.
- The user profile returns `null` name and surname when the identity token has no given name, instead of crashing.
- 500 responses return a generic message. The real error is still logged server-side.

## Capabilities

### New Capabilities
- `campaign-details`: Who can read a campaign's details and which fields each role sees.
- `campaign-invites`: Who can create a campaign invite and the outcomes of creating one.
- `character-hp`: Rules for updating a character's hit points.
- `user-profile`: The authenticated user's profile built from identity token claims.
- `api-errors`: How errors are reported to API clients.

### Modified Capabilities

None. These are the first specs in the project.

## Impact

- **API**: `GET /core/api/v1/campaign/{campaignID}` and `POST /core/api/v1/invite` can now return 403. Clients that showed a campaign to non-members must use `GET /core/api/v1/invite/{inviteHash}` instead.
- **Code**: campaign domain policy and details use case, invite create use case and module wiring, character HP use case and row mapper, user profile mapper, shared HTTP error mapping.
- **Docs**: Swagger annotations for the two endpoints above (regenerated by CI).
