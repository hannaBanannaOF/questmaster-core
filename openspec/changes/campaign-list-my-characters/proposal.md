# Proposal

## Why

The frontend dashboard highlights the campaign a player can continue, but the campaign list does not say which of the player's characters are in it. Showing "you play Harvey Walters in this campaign" would take the campaign details request for each campaign. A player can have more than one character in the same campaign (see `campaign-list`), so the answer is a list.

## What Changes

- Each item of `GET /core/api/v1/campaign` gets `my_characters`: the requester's characters in that campaign, as `{ slug, name }`, ordered by name. It is empty when the requester only runs the campaign.

Out of scope: the DM's name. The core does not store users (names come from the access token of each request), so returning another user's name needs a user projection first, which is a separate change.

## Capabilities

### New Capabilities

None.

### Modified Capabilities
- `campaign-list`: Adds the requester's characters to each campaign in the list.

## Impact

- **API**: Additive, a new field in the campaign list items.
- **Code**: campaign list query (or a second query by campaign ids), read model, response and mapper, Swagger annotation (regenerated by CI).
- **Frontend**: the "continue playing" card shows the player's character, and campaign cards can show it too.
