# Proposal

## Why

The frontend dashboard shows how many campaigns the DM has in each status (ACTIVE, DRAFT, PAUSED, ARCHIVED). Today it counts them by loading the whole campaign list. With paginated lists (see `paginate-list-endpoints`), that would take four requests with a `status` filter just to read four `total` values.

## What Changes

- New `GET /core/api/v1/campaign/counts`, returning the number of the requester's campaigns in each status: `{ "DRAFT": n, "ACTIVE": n, "PAUSED": n, "ARCHIVED": n }`. Every status is always present, with 0 when there is none.
- Accepts the same `role` filter as the campaign list (`dm` or `player`); without it, counts both roles.

Out of scope: counts for characters (the character list `total` already covers them) and counts by game system.

## Capabilities

### New Capabilities

None.

### Modified Capabilities
- `campaign-list`: Adds the per-status counts of the requester's campaigns.

## Impact

- **API**: Additive, a new endpoint.
- **Code**: campaign repository count query, new use case and handler, route, Swagger annotation (regenerated by CI). Reuses the `role` filter parsing from `paginate-list-endpoints`, so this change goes after it.
- **Frontend**: the DM tab of the dashboard reads the counts instead of counting a full list.
